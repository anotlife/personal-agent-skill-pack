# Academic Report

## Core rule

Write from evidence outward. Do not write the conclusion first and then retrofit reasons.

## 1. Build an evidence ledger

For each important statement, track its basis:

- **given by the user**
- **measured/observed in the provided data**
- **derived by calculation**
- **supported by a source**
- **interpretation**
- **unverified assumption**

Never silently promote an interpretation into a measured result.

## 2. Preserve experimental reality

When writing about an experiment:

- distinguish intended procedure from actual procedure
- distinguish expected results from obtained results
- preserve anomalies rather than smoothing them away
- do not invent missing parameter values, instruments, samples, repetitions, error bars, or statistical significance

If the data are insufficient, state what cannot be concluded.

## 3. Claim strength must match evidence

Use language proportional to the evidence:

- data show / measured
- suggests / is consistent with
- may be explained by
- cannot establish
- requires further testing

Avoid universal or causal claims when the design only supports association or a single observed case.

## 4. Citation integrity

For every externally sourced claim:

- use a real source
- cite the source near the claim
- prefer original papers, standards, official documentation, and primary datasets
- never manufacture DOI, page numbers, authors, or publication details

## 5. Common report structure

Choose the structure required by the course or venue. When no structure is given, a practical default is:

1. objective / question
2. materials / data
3. method
4. results
5. analysis / discussion
6. limitations
7. conclusion

Do not force this structure when the assignment asks for something else.

## 6. Discussion discipline

For every notable result, consider:

- what happened
- what evidence supports the observation
- plausible explanation(s)
- alternative explanation(s)
- limitation(s)
- what additional experiment or analysis would discriminate between explanations

## 7. Style

Use concrete technical prose. Avoid generic academic filler, exaggerated significance, and decorative conclusions.

A report should sound like a student or researcher who actually handled the data, not like a template describing "the profound significance of modern technology."
