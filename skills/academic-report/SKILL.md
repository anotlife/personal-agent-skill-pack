# Academic Report

## Progressive loading

1. Use the core rules below for any academic deliverable.
2. For data-heavy work, read `references/evidence-ledger.md`.
3. Before drafting, read `references/section-playbook.md`.
4. For numbers, tables, and figures, read `references/quantitative-reporting.md`.
5. For interpretation and discussion, read `references/uncertainty-and-causality.md`.
6. For citations, read `references/citation-integrity.md`.
7. If the work must be reproducible by someone else — or by you next week — read `references/reproducibility.md`.
8. Weak model: read `references/weak-model-mode.md` first.

## Core rules

- **Write from evidence outward.** Do not draft a conclusion and retrofit support for it. The order of writing is not the order of reasoning.
- **Assign a basis to every important statement** — given, observed, derived, source-backed, interpretation, assumption, unknown — and never promote one category to another silently.
- **Do not invent** missing parameters, samples, instruments, repetition counts, error bars, significance values, temperatures, concentrations, timings, or experimental outcomes. A blank in the record is a finding; a filled-in guess is fabrication.
- **Preserve anomalies and limitations.** A result that does not fit is the most informative thing in the report, and smoothing it away is the most common form of academic dishonesty an AI commits.
- **Match claim strength to evidence.** One run supports one observation, not a rule.
- **Use real citations.** Never manufacture bibliographic details.
- **Keep technical precision.** "Making it sound less robotic" must not delete domain-specific meaning, hedging that carries information, or units.
- **Follow the assignment's own structure.** If the instructor gave headings, a rubric, a word limit, or a format, those outrank any generic template.
- **Never write a report as though an experiment was performed when it was not.** If you are helping with prose about work the user did, you write about *their* data, and you say when a number is missing.

## What the AI must not do

- Produce results the user did not obtain.
- Present a plausible mechanism as a measured finding.
- Fill a required table with plausible values.
- Convert "we expected X" into "we observed X".
- Upgrade a correlation into a cause because the report flows better that way.
- Delete an outlier to make a trend cleaner.
- Write a discussion that answers a different question than the one the report asked.

## Final gate

- Every number traces to data or to a stated derivation.
- Every claim's strength matches its basis.
- Anomalies, limitations, and failed attempts are present and explained.
- Citations are real and support the claims they sit beside.
- The report's structure follows the assignment, not a default template.
