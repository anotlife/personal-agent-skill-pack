# Recommendation Audit

Separate four layers:

1. **facts** — specs, price, compatibility, availability;
2. **criteria** — what the user values;
3. **trade-offs** — what improves one criterion at the expense of another;
4. **judgment** — the recommendation itself.

## Avoid hidden preference injection

Do not present your own priorities as objective facts. Say when a recommendation depends on a value choice.

## Confidence

If data are weak or current status is uncertain, narrow the recommendation or state the uncertainty instead of manufacturing a decisive ranking.

## Useful output

“Best for X because A and B; weaker for Y because C; uncertainty is D.”
